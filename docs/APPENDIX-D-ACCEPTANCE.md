## 3. `C-*` 配置面验收（API / 模型 / 凭据）

| ID | 用例 | 操作 | 期望的可观测结果 |
|---|---|---|---|
| `C-01` | 零路由启动 | 首次打开、未配置任何 provider | **不崩溃**；引导配置第一个 provider；composer 停用并给出明确文案 |
| `C-02` | 新建 OpenAI 兼容路由 | 填 `id`/`displayName`/`baseURL` | 路由名文法校验 `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`；非法名即时报错 |
| `C-03` | 密钥只写不读 | 保存密钥后重新打开设置 | 显示"已配置"状态点；**任何读 API 都不返回值**（含 DevTools 检查网络响应） |
| `C-04` | 密钥脱敏 | 触发一次错误 + 导出诊断 | 错误信息与导出文件中**不含密钥的任何字符**（含前缀、长度、指纹） |
| `C-05` | 持久化红线 | ① 默认配置下保存密钥 ② 显式勾选"记住密钥"后保存 | ① **仅 `sessionStorage` 有**，`localStorage` **无**（刷新即失效，与冻结文档一致）；② 此时 `localStorage` 才有，且已写 `decision.record`。**两种情况都不得出现** IndexedDB / OPFS / Cookie / SW Cache |
| `C-06` | 获取模型列表 | 点"获取可用模型" | 调 `GET {baseURL}/models`；字段归一化生效；**发现结果只做候选，需点"添加所选"才写入** |
| `C-07` | 坏数据不毁端点 | 端点返回含缺 `id` 条目的列表 | 该条目被跳过，其余正常显示 |
| `C-08` | 测试连接（成功路径） | 有效密钥 + 真实模型，`max_tokens: 5` | 返回"已连通"；**不断言返回文本**（推理模型 `content` 可能为 `null` 但连接是好的） |
| `C-09` | **CORS 失败与鉴权失败可区分** | **两种构造方式**：① CORS 失败 —— 指向一个**真实但未返回 `Access-Control-Allow-Origin` 的端点**（可用一个本地静态服务器返回 JSON 而不带 CORS 头，或指向已验证会拦 CORS 的第三方端点）；② 鉴权失败 —— 对**已验证支持 CORS 的通道**用**无效密钥**发起真实请求 | ① 显示"无法从浏览器访问该端点（可能是跨域限制、网络中断或密钥错误）"+ 排查指引；② 显示"鉴权失败（401/403）：检查 API 密钥"。**两者文案必须不同**（这是本用例的全部意义） |
| `C-10` | 稳定错误码路由 | 构造 `MISSING_CREDENTIAL` / `UNKNOWN_MODEL` / `UNSUPPORTED_REASONING_EFFORT` | 三者均在**网络 I/O 之前**失败；文案分别正确；**不解析 message 文本** |
| `C-11` | 会话级模型切换 | 会话中途切换 provider/model | 插入可见通知「以上内容由 A 生成；会话继续使用 B」；**请求序列继续**；`model/selection` + `request/header` 事件已写 |
| `C-12` | 仅 effort 变化 | 只改 `reasoningEffort` | **不插入切换通知**（避免噪声） |
| `C-13` | 模型不可用（**三段式**） | ① 目录里选不到该模型 ② **目录成功加载**且该 id 确实不在其中 → 尝试发送 ③ **目录加载失败**（`failure`）→ 尝试发送 | ① 选择器里不出现它；② **发送被阻断**（不采纳 DSH 的宽松提交路径，见 PRD §8.6）+ 横幅「当前选中的 X 已不在模型目录里」+ [改选可用模型] [检查路由配置]；③ **允许发送但显示警告** + [重试拉取目录]（**不得**因目录抖动而阻断一 个本来可用的模型） |
| `C-14` | 单 provider 失败隔离（**两段式**） | ① 一个 provider 目录加载失败、其他正常 ② 在 ① 状态下对**失败 provider 的已保存模型**发送 | ① 它显示为一行 `failure`，**其他 provider 仍可用**；空模型分组被过滤；② **允许发送 + 警告**（见 `C-13` 情形 ③） |

## 8. `W-*` Web 适配风险验收

| ID | 用例 | 判据 |
|---|---|---|

per-doc:  coverage / mojibake_rate / is_scanned / two_column_risk / header_footer_ratio

## 10. 演示脚本（15 分钟）

> **v2.0 重写**：演示主线从"语料→检索→起草"改为**"命题 → 检索 → 实验设计确认 → 七步实证 → 论文初稿"**。三次突袭全部保留，但换了位置。

| 6–7.5' | 文献检索：命中**全部来自用户文献库**；**随机点一个引用回跳原 PDF 原页高亮** | 🔥 **突袭 3** |
| 7.5–9' | **实验设计页**：七分区全貌 → 指出 1 项 `fail` 与 2 项警告 → **现场处置后点「确认并开始实证」** | — |

| 12.5–13.5' | **论文初稿**：九章结构 + 逐段生成；默认《中国工业经济》风格；**现场问一个语料里没答案的问题 → 拒答四段结构** | 🔥 **突袭 4** |
| 13.5–14.5' | **刷新页面** → 现场复原（阶段、设计、产物、初稿全在） | — |

**产品内置的"随机突袭自检"按钮**：随机抽一篇、随机抽一段、随机抽一个引用，现场点回跳。

> **一键验真的三个动作**（把"可被突袭检验"写进产品本身，而不是答辩话术）：
> 1. **换数据**：现场改一行数据重跑③，系数变化且对账报告标出差异；
> 2. **换命题**：现场换一个命题重跑全链，验证不是硬编码；
> 3. **查数字**：随机点正文一个数字 → 跳到结果表 → 跳到脚本行。
