# 一页纸决策卡（可截图放进 demo 的"关于"页）

## 定位一句话
> 以**你自己上传的文献库**为唯一事实来源、**逐句可回溯出处**的研究与写作工作站。
> 卖点是**可核查**，不是**智能**。

## 唯一主流程
```
选文件夹(≤300 PDF) → 本地解析/分块/建索引(可中断可续) → 语料体检报告
   → 章节↔文献映射(可手改) → 在某章检索→提纲→逐段起草(带 citation chip)
   → 点 chip 回跳原 PDF 页内高亮 → 导出证据包
```

## 能力三态（写进 UI，别含糊）
| 态 | 内容 |
|---|---|
| **MVP（敢验收）** | 批量入库+持久化、抽取质量诊断、结构化分块、章节映射、关键词检索、检索式起草+出处回跳、证据包导出 |
| **演示（只证技术通）** | 本机小模型生成、Pyodide 计量脚本执行、划词追问、已发表论文结构化解读 |
| **不做（主动声明）** | 抓取知网/第三方全文、查重降重、"零幻觉"、跨设备同步、全库塞上下文、100% 版式正确 |

## 技术栈（冻结版）
- **解析**：pdf.js（Worker 内，按页流式，禁整文件读入）
- **OCR**：tesseract.js chi_sim，**默认不自动跑**，需用户显式同意
- **表格/文档**：SheetJS / mammoth.js
- **检索**：BM25（中文用字符二元组）+ 本地向量（Int8 量化，384/512 维）→ RRF 融合 → 可选 MMR
- **向量检索**：起步暴力余弦（Float32Array）；>5 万 chunk 再评估 HNSW(WASM)
- **存储**：OPFS（大对象分片）+ IndexedDB（元数据）；`estimate()` 预检 + `persist()` 申请
- **统计**：Pyodide + statsmodels/linearmodels（主）；JS 手写 OLS/within（快通道）
- **生成**：默认 **检索式模板组装（模式 B）**；可选 WebLLM（WebGPU）；BYOK 仅 `sessionStorage`
- **可视化**：ECharts **或** Vega-Lite（择一）
- **离线化**：Service Worker 缓存 pdf.js WASM / 词表 / 量化模型 / Pyodide wheels

## 容量预算（300 篇 / 假设均 15 页）
| 量 | 估算 |
|---|---|
| 页数 / chunk | ≈4500 页 / 6 万–15 万块 |
| 纯文本入库时长 | **3–8 分钟**（含 OCR：30–90 分钟） |
| 向量常驻（Int8, 6 万×384） | ≈23MB（30 万则 ≈115MB，Float32 全量不可行） |
| 存储占用 | **200–500MB** |
| 检索延迟目标 | P95 < 150ms（语义未就绪时只跑 BM25） |

## 降级九条（缺一不可）
FS Access 不可用 → 退回 input 多选 · 无 OPFS → IndexedDB+内存 · 隐私模式 → 纯会话+强制导出提醒 ·
配额不足 → 停向量保 BM25 · 无 WebGPU → 关生成转检索式（embedding 走 WASM）·
模型下载失败 → 关键词 only · 中途崩溃 → 清单续跑 · **单篇失败不拖垮整批** · **被驱逐可导入恢复**

## 必做（最容易被漏、但决定成败）
1. **语料体检报告**：每篇给出覆盖率/乱码率/扫描件/双栏风险，失败可见
2. **引用强制校验**：`[n]` 必须映射到真实 chunk，否则标红降级为"无来源"
3. **拒绝回答机制**：数据不满足识别策略时明确说"不支持 + 理由"
4. **导入/恢复闭环**：加密导出包（否则一次驱逐 = 产品死亡）
5. **黄金语料回归集**：50 篇含双栏/扫描/CJK 子集字体/公式/表格，改解析必跑
6. **demo 内"随机突袭自检"按钮**：随机抽一篇/一段/一个引用，现场点回跳
7. **推理位置状态条**：常驻显示 本机/WebGPU/模型名/量化/tok·s⁻¹/本次未联网

## 迁移到本地 App：复用什么、换什么
| 完全复用 | 接口复用·实现替换 | 必须替换 |
|---|---|---|
| 领域模型 schema、内容哈希+清单状态机、检索融合公式(RRF/MMR)、导出证据包格式、UI 组件、进度事件协议、**黄金语料回归集** | `CorpusStore`（OPFS+IDB → SQLite）、`Retriever`（MiniSearch → FTS5 / sqlite-vec）、Embedding（transformers.js → ONNX/llama.cpp） | 本地生成（WebLLM → llama.cpp/Ollama）、统计执行（Pyodide → 真 Python + pyfixest）、文件访问（FS Access → 原生目录监听） |

**现在就要做的三件事**：① 四个接口先定死（CorpusStore / Retriever / Generator / Executor）；② 索引元数据写死可迁移头（`embedding_model_id@ver`、`dim`、`quantization`、`tokenizer_id`、`chunker_ver`、`schema_ver`）；③ 建黄金语料回归集。

## 五大风险与处置
| # | 风险 | 处置 |
|---|---|---|
| R1 | 浏览器存储可被驱逐 → "我的东西丢了" | persist() + 如实告知 + 导出/恢复闭环 |
| R2 | PDF 解析质量不可控（CJK 子集字体/扫描/双栏） | 20 篇抽样量化；体检报告前置；失败可标注可补救；抽样太差就改定位为半自动工作台 |
| R3 | 索引时长杀死交互体验 | 后台批处理 + 边建边用 + 快速模式 + 实测外推的剩余时间 |
| R4 | 小模型质量不够、且会编造引用 | 默认检索式组装 + 引用强制校验 + 定位为"骨架与素材编排" |
| R5 | 实证模块制造统计误用 | Pyodide+成熟库、识别策略前置检查、拒答、用公开数据做系数对账 |
| R6 | 合规/使用条款 | 不抓取、不建可再分发的语料库、不导出全文、责任声明 |
| R7 | 四块能力并行做不深 | 收窄为一条主流程 + 三种输出形态 |
| R8 | demo 可信度可被"演"出来 | 现场换一篇非预置 PDF、现场点 chip 回跳、现场改数据重跑比对 |

## 五个待验证假设（W0 就要验，别等做完）
| # | 假设 | 验证 | 若为假 |
|---|---|---|---|
| A1 | 真语料抽取质量可支撑章节-引文映射 | 20 篇真实抽样量化 | 降级为半自动标注工作台 |
| A2 | 300 篇能在目标机型索引完且不崩 | 造 300 篇压测，记录峰值内存/时长/配额 | 收紧至 100 篇或分批项目制 |
| A3 | 用户能接受分钟级后台索引 | 可用性小样本 | 快速/深度双档 |
| A4 | 检索式组装产出用户愿用的骨架 | 3 位真实写作者试用批注 | 重定义"撰写"承诺 |
| A5 | 计量脚本可复现、系数可对账 | 用公开复现包交叉验证 | 关闭实证生成，只留设计+检查清单 |

## 最终判断
> 在纯前端约束下，可信的 AI 演示不是**把模型塞进浏览器**，而是**把"出处"塞进每一个结论**。
> 模型可以小，检索可以土；只要每个论断都能一键回到原 PDF 的那一页那一块，这个 demo 就比市面上大多数"AI 写论文"可信得多。
