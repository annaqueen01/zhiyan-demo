## 1. 需求背景

### 1.1 用户是谁，卡在哪

| 画像 | 现状 | 卡点的本质 |
|---|---|---|
| **经管本科生**（毕设/课程论文） | 第一次接触经管论文，不知道一篇论文长什么样、有哪些部分、每部分该写什么 | **没有范式认知**：不知道"应该做什么" |
| **经管硕士生**（学位论文/小论文） | 有题目，但不知道从想法到成稿的流程；实证代码靠抄师兄师姐的代码改 | **没有流程能力**：不知道"下一步做什么" |
| **跨专业考研/转专业学生** | 计量基础薄弱，看不懂回归表，更写不出结果解读 | **看不懂结果**：不知道"这张表说明了什么" |

### 1.2 三个真实痛点

**痛点一：论文写作范式与流程无人系统教。**
经管论文有强范式（引言→文献综述→理论假说→研究设计→数据与变量→实证结果→稳健性→机制/异质性→结论与政策含义），但这套范式**不在任何一门课的考纲里**。学生第一次写论文时，最大的困难不是"不会写句子"，而是**不知道一篇合格论文的骨架长什么样、每个部分的评价点在哪里**。老师有经验但没时间一对一系统化指导——一个导师带 5–15 个学生，能给的是一轮批注，不是一套流程训练。

**痛点二：实证部分是最黑的黑箱。**
从"我有一个数据文件"到"我有一张能写进论文的基准回归表"，中间要经过：数据清洗、变量构造、描述性统计、基准回归、稳健性检验、内生性处理、异质性分析、机制检验。每一步都有方法论前提（固定效应怎么选、标准误聚在哪一层、平行趋势能不能检验），而**通用 AI 对话工具会直接给你一段能跑但结论不可信的代码**。学生既无法判断代码对不对，也无法判断结论能不能这么说。

**痛点三：通用 AI Agent 在学术场景上不可信。**

| 失效模式 | 具体表现 | 对学生的伤害 |
|---|---|---|
| **幻觉** | 编造不存在的文献、编造参考文献条目 | 写进初稿后被导师一眼看出，返工 |
| **质量失控** | 语言风格不像学术论文（口语化、营销腔、AI 味） | 初稿不可用，等于重写 |
| **实验设计错误** | 不问数据结构就给 DiD；不给聚类层级；把相关性写成因果 | **最严重**：产出学术上站不住脚的结论 |
| **结果解读错** | 把不显著说成"有显著影响"；把边界显著说成"稳健" | 学生照着抄，错误被固化 |
| **无过程** | 只给一个答案，不给中间产物 | 学生学不到东西，也无法交付过程性材料 |

### 1.3 我们的机会

学生真正需要的不是一个"更聪明的聊天框"，而是：

> **一个内置经管论文范式、以你自己的文献库为知识底座、能带你从命题走到成稿、每一步都留得下过程性材料的科研助手。**

关键洞察：**"过程性文件"既是产品价值，也是教学载体。** 每一步都产出「可执行代码 + 结果文件 + 结果解读」三件套，学生不仅拿到了论文，还拿到了一份**可以照着学的研究流程示范**——这是通用 Agent 给不了的。

### 1.4 与既有能力的关系（诚实说明）

`可追溯（每个论断可回跳原文）` 在本版本中**不再是卖点叙事，但仍作为质量保障机制保留**，理由：

1. **防幻觉**：所有文献引用必须来自用户自己的文献库，引不到就不写——这是"幻觉率低"的技术实现，不是宣传语；
2. **防实验设计错误**：识别策略判定要能指到具体的检查项与数据结构字段；
3. **教学价值**：学生点开一个引用能看到原文那一段，本身就是最快的学术写作训练。

> **一句话**：可追溯从"我们的卖点"变成"我们的实现手段"。对外讲的是**"帮你写出 80 分的论文"**，对内做的是**"每一句都有据、每一步都可查"**。

## 2. 需求目标

### 2.1 产品定位（一句话，写进 UI「关于」页）

> **以你自己的文献库为知识底座、带你从研究想法走到一篇合格论文的经管科研助手。**
> 目标不是"替你写"，而是**让你第一次也能跑完一遍完整的研究流程，产出一篇至少 80 分的合格论文，并且知道每一步为什么这么做。**

### 2.2 目标用户与典型场景

| 场景 | 用户 | 成功标准 |
|---|---|---|
| **S-A 毕设起步**（主场景） | 本科生，只有模糊的感兴趣方向 | 30 分钟内拿到一份可执行的实验设计 + 一份论文骨架 |
| **S-B 小论文冲刺** | 硕士生，有数据和题目，缺流程 | 提交命题+数据 → 拿到七步实证全套过程文件 + 论文初稿 |
| **S-C 读懂一篇论文** | 任意学生，要读懂一篇已发表论文 | 拿到结构化解读卡（研究问题/数据/识别策略/结论/局限）+ 可借鉴点 |

### 2.3 "80 分合格论文"的可操作定义

"80 分"不能只是口号，必须拆成可检查的维度（这也是产品的质量门）：

| 维度 | 权重 | 合格线（80 分档） | 产品如何保障 |
|---|---|---|---|
| **结构完整度** | 25% | 九大部分齐全，无缺章；每部分含必要要素 | 范文结构模板 + 提纲签核门 |
| **实证规范度** | 30% | 基准回归有聚类标准误、有固定效应声明、有 N 与组内 R²；稳健性 ≥3 项；内生性有交代 | 实验设计确认门 + 七步流水线 + 检查清单 |
| **文献支撑度** | 20% | 关键论断有本文库内的真实引用；综述按流派/策略/分歧组织而非罗列 | 引用强制校验（四查） |
| **语言风格** | 15% | 符合经管期刊学术语体（默认对标《中国工业经济》） | 风格参考文献 / 默认期刊风格包 |
| **结论审慎度** | 10% | 措辞强度与证据强度匹配（相关证据不写因果） | 措辞强度门控（动词白/黑名单） |

> 总分 = 各维度得分 × 权重。**任一维度低于 60 分档即整体不合格**——这是"木桶"规则，防止用漂亮语言掩盖实证缺陷。

### 2.4 成功判据（Demo 验收）

| # | 判据 | 检验方式 |
|---|---|---|
| G1 | 现场输入一个**非预置**的研究命题，能走完全链 | 评委现场出题 |
| G2 | 检索命中的文献**全部来自用户自己的文献库**，零编造 | 随机点 5 个引用核对原文件 |
| G3 | 实验设计**先出方案等确认**，未确认不跑任何数据 | 现场观察：确认前数据库无任何回归输出 |
| G4 | 七步实证**逐步产出**「代码 + 结果 + 解读」三件套，可下载 | 现场数文件数 = 7×3 |
| G5 | 结果解读与结果文件**数值一致**，不夸大 | 现场比对解读句与系数表 |
| G6 | 论文初稿按指定风格文献（未指定则《中国工业经济》风格）组织 | 现场比对行文风格与结构 |
| G7 | 刷新浏览器后项目现场复原 | 现场 F5 |
| G8 | 断网可走完演示主线（回放兜底） | 现场拔网线 |
| G9 | 配置自定义模型 API 后走真实调用，且能检测连通性 | 现场填 key 测试 |

### 2.5 明确不做（写死在 UI 与 README）

1. **不联网抓取**知网或任何第三方全文。文献与数据**只能由用户提供**（本地文件夹或上传）。
2. **不做查重、不做降重**。没有权威比对库，做了就是骗人。
3. **不承诺"零幻觉"**，但承诺**不编造文献**：引不到就写『此处待补文献』。
4. **不代替用户做学术判断**：识别策略不成立时给"做不了 + 理由 + 你能补什么"，不硬跑一个漂亮结果。
5. **不把整库塞进上下文**。任何问答都是"检索 → 片段 → 引用"。
6. **不承诺跨设备同步**。项目导出包是唯一同步/备份通道。
7. **不承诺 100% 版式正确的 PDF 解析**。承诺失败可发现、可标注、可人工补救。
8. **不代写整篇、不伪造数据、不提供 p-hacking**（含"帮我调成显著"）。
9. **文稿通道本期只承诺 PDF**；Word/Excel 需按 `CorpusStore` 端口另加 adapter。

| 触发 | 行为 |
|---|---|

| 点「资源库 › 数据库 / 文献库」 | 打开该资源的**管理抽屉**（见 R-02），不离开当前页面 |
| 输入 Prompt 后按发送 | 创建项目 → **对话区下沉到页面下方**（见 R-03）→ 三张演示卡**隐藏** |

**其他需要开发关注的内容**：

1. **演示卡不是空状态的主体，而是"演示数据入口"** —— 空状态的主体是**主对话框**。这条是明确的产品决策：不要让学生面对一个空白页不知道说什么。
2. **左栏是一级导航，不是 Tab**。资源库下的"数据库/文献库"是**抽屉**，不是新页面，也不是 Tab —— 避免出现两套导航体系。
3. **空状态 → 项目态的过渡必须是"同一页面内的布局下沉"**，不是路由跳转到另一个页面。理由：用户的心理模型是"我开始跟它说话了"，不是"我打开了一个新工具"。
4. 首次访问时左栏应自动展开；之后记住用户选择（`localStorage`，非敏感）。
5. 演示卡点击后若用户已有进行中的项目，需二次确认（避免误覆盖现场感）。

**功能名称**：资源库管理抽屉（数据库 / 文献库）

**布局**：从右侧滑出的抽屉，宽 `560px`；内部上下分区 —— 上为**来源选择**，下为**已入库资源列表 + 检索预览**。

```
┌────────────────────────────── 资源库 · 文献库 ────────────── ✕ ─┐
│  来源：  ● 选择本地文件夹    ○ 上传到浏览器                      │

│  ▸ 我的毕设参考               43 篇 · 1.1 万块 · 建索引中 62%   │
│  ── 检索预览 ────────────────────────────────────────────────  │

**位置**：左栏一级导航 → 资源库 → 数据库 / 文献库。

**内容**：

| 子模块 | 内容 |
|---|---|
| 来源选择 | 二选一单选：**选择本地文件夹**（File System Access API）/ **上传到浏览器**（`<input webkitdirectory>` + 拖拽） |

| 来源 | 落盘位置 | 检索 | 匹配 | Agent 可调用 | 刷新后 |
|---|---|---|---|---|---|

| 上传到浏览器 | 存 OPFS（分片） | ✅ | ✅ | ✅ | ✅ 直接可用 |

**字段取值**：

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `source.kind` | enum | `local-handle` \| `browser-upload` | 来源类型 |
| `source.dirName` | string | 目录名 | — |
| `doc.doc_id` | string | `SHA-256(size + 首尾1MB + 文件名)` | **去重靠它，不靠文件名** |
| `doc.parse_status` | enum | `pending` \| `parsing` \| `parsed` \| `failed` \| `ocr-needed` | — |
| `doc.text_trust` | enum | `high` \| `medium` \| `low` | **不允许空白** |
| `chunk.chunk_id` | string | `hash(doc_id + char_range + 文本哈希)` | 幂等与可续跑的地基 |
| `chunk.locator` | object | `{page:int, bbox:[x,y,w,h], char_range:[start,end]}` | 回跳用 |
| `dataset.colType` | enum | `numeric` \| `categorical` \| `datetime` \| `id` \| `unknown` | 列类型推断 |
| `dataset.panelShape` | enum | `panel` \| `cross-section` \| `time-series` \| `unknown` | 面板结构识别 |
| `index.status` | object | `{bm25:'ready'\|'building', vector:0-100}` | 分阶段就绪 |

**极限值与单位**：

| 项 | 极限 | 单位 | 超限行为 |
|---|---|---|---|
| 文献库文件数 | 300 | 篇 | 提示分批，拒绝整批入库 |
| 单文件大小 | 100 | MB | 跳过并记入失败清单 |
| 文献库总大小 | 2 | GB | **入库前**预检配额并给三档方案 |
| 数据库单文件 | 500 | MB / 500 万行 | 提示抽样或裁剪 |
| 数据库文件数 | 20 | 个 | — |
| chunk 长度 | 350–700（重叠 15%） | 中文字 | 不跨章节 |
| 索引构建时长 | 纯文本 3–8 min；含 OCR 30–90 min | 分钟 | 必须显示区间 + 置信度 |

**交互设计**：

| 触发 | 行为 |
|---|---|
| 选择来源方式 | 切换后下方操作区形态随动（文件夹授权 / 拖拽上传） |
| 入库中 | 进度卡显示逐篇 + 逐页 + 索引分片；**BM25 就绪即可用**，向量后台补建 |
| 向量未就绪时检索 | 自动降级 BM25-only，UI 明示"语义检索未就绪" |
| 点任一片段预览 | 右侧证据抽屉切为该 chunk 详情；若 PDF 可预览则同屏高亮 |
| 点单篇诊断等级 | 展开该篇六项指标；红灯可点进原文页看坏在哪 |
| 删除资源集 | 二次确认；提示"引用该库的项目将标记为待重授权" |

**其他需要开发关注的内容**：

1. **本地文件夹必须"只记句柄、不复制文件"**——否则 2GB 语料会被复制两份。
2. **重复上传同一文件不重算**（`doc_id` 命中直接跳过），这是"可续跑"的基础。
3. **失败隔离**：单篇解析失败**不得**中断整批，进"待人工处理"列表且清单可导出。
4. 建索引是**长任务**，必须支持中断 + 续跑 + 刷新后恢复（靠 `chunk_id` 内容哈希）。
5. OCR 默认**关闭**，开启需逐项勾选并看到时长与配额代价。
6. 检索预览的命中片段**必须带出处**（这是"不编造"的第一道用户可见证据）。

**极限值与单位**：

| 项 | 极限 | 单位 |
|---|---|---|

| 连接测试超时 | 15 | 秒 |
| 发现请求响应上限 | 4 | MiB |
| 密钥长度上限 | 512 | 字符 |
| 请求超时 | 300,000（默认） | ms |

**交互设计**：

| 触发 | 行为 |
|---|---|
| 保存密钥 | 显示"已配置"状态点；**任何读 API 都不返回值**；清除密钥需二次确认 |
| 点「测试连接」 | 显示 `testing` → 结果徽标 + 耗时；**必须走成功路径**（有效密钥 + 真实模型，`max_tokens:5`） |
| 测试失败 | 按稳定 code 分文案：`401/403` → 检查密钥；**CORS 被拦 → 明确说"无法从浏览器访问该端点"**，与密钥错误**分开** |
| 点「获取可用模型」 | `GET {baseURL}/models`；列出候选 + [添加所选]；**不自动写入配置** |
| 切换模型 | 会话内切换**不重置会话**，插入可见通知「以上内容由 A 生成；会话继续使用 B」 |
| 删除预置路由 | 禁止（置灰 + 说明） |
| 密钥持久化 | 默认 `sessionStorage`（刷新即失效）；用户可**显式勾选**"记住密钥"（`localStorage`），默认关闭 |

**其他需要开发关注的内容**：

1. **绝不在交付物里出现任何真实密钥**（含注释、示例"演示 key"）。
2. **错误用稳定 code 路由，绝不解析 message 文本**（`MISSING_CREDENTIAL` / `INVALID_CREDENTIAL` / `AUTH` / `RATE_LIMIT` / `QUOTA` / `CONTEXT_WINDOW_EXCEEDED` / `TRANSPORT` / `UNKNOWN_MODEL` / `UNSUPPORTED_REASONING_EFFORT`）。
3. **"目录里没有该模型"的闸门条件是"目录成功加载且该 id 确实不在其中"**；目录拉取失败/断网时**允许发送但警告**，不能因为端点抖动把可用模型锁死。
4. 连通性检测**不能用鉴权失败来推断 CORS 是否可用**——部分提供方成功与失败走不同网关，错误响应反而不带 CORS 头，看起来与"服务坏了"一样。
5. **CORS 是纯前端直连的真实风险**：已核实的支持情况见 §5.9；四档连接方案（本机模型 / 已验证支持 CORS 的云端 / 用户自有中转 / 离线回放）要写进帮助文案。

### 4.5 R-05 研究命题提交与解析 `P0`

**功能名称**：命题解析（Research Question Scoping）

**布局**：对话区内的一张**结构化确认卡**（不是纯文本回复）。

```
┌─ Agent ────────────────────────────────────────────────────────┐
│ 我按你的命题拆成 5 个槽位，有不对的直接改：                      │

| 步 | 步骤 ID | 做什么 | 产出重点 |

| ① | `data-prep` | 数据读取、清洗、变量构造、样本筛选、异常值处理 | 清洗日志（删了多少行、为什么）、变量描述表 |

| ⑦ | `mechanism` | 机制检验（中介/渠道，按设计） + 措辞降级 | 机制回归表 + 措辞强度声明 |

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|

| `step.progress` | object | `{phase, done, total, unit, etaRangeMs?, etaConfidence}` | 结构化进度 |
| `artifacts.code` | object | `{path, language:'python', runnable:true, envLock}` | 可执行代码文件 |
| `artifacts.result` | object | `{path, format:'csv'\|'md'\|'json', tables[], figures[]}` | 结果文件 |
| `artifacts.interpretation` | object | `{path, format:'md', sentences[{text, boundCells[], wordingStrength, modelMode}]}` | 解读文件 |
| `result.cells[]` | array | `{cell_id, term, coef, se, t, p, stars, n, withinR2, nClusters, feTerms}` | 每个数字一格 |
| `interpretation.modelMode` | enum | `rule` \| `rule+llm` | 解读生成方式（**诚实标注**） |
| `step.rerunCount` | int | ≥0 | 重跑次数留痕 |

**极限值与单位**：

| 项 | 极限 | 单位 |
|---|---|---|
| 观测数 | 5,000,000 | 行（超出提示抽样） |
| 变量数 | 200 | 列 |
| 单步执行时长 | 30 s – 20 min | — |
| 代码文件 | ≤ 2,000 | 行/步 |
| 结果表 | ≤ 20 | 张/步 |
| 解读句 | ≤ 200 | 句/步 |
| 重跑次数 | 无上限（但留痕） | 次 |

**交互设计**：

| 触发 | 行为 |
|---|---|
| 设计确认 | **自动从①开始顺序执行**；每步完成即产出三件套 |
| 步骤条点击 | 跳到该步查看（已完成的直接看，未开始的只显示计划） |
| 点「暂停」 | 当前步跑完当前执行项后暂停（不硬中断）；已完成结果保留 |
| 点「重跑本步」 | 作为**新 run** 执行，旧结果保留可对比；写 `step.rerun` 事件 |
| 点「跳到下一步」 | 跳过当前步（记为 `skipped` + 理由），在论文初稿里标注"未做" |
| 点「查看与设计的一致性」 | 弹出对照：设计项 vs 实际执行项，缺哪项高亮 |
| 点下载 | 单步三件套打包下载；顶部另有"下载全部过程文件（zip）" |
| 执行失败 | **展示失败**（不静默吞 traceback）+ 给三条处置：改设计 / 改数据 / 跳过并标注 |

**其他需要开发关注的内容**：

1. **每步必须真的产出可执行代码文件**——不是伪代码、不是片段。脚本头强制含 `seed / data_hash / env_lock / cluster / sample_filter`。
2. **结果解读的数值必须与结果文件逐格一致**（`boundCells` 绑定 `cell_id`）；解读不得出现结果里没有的数字。**这是"不夸大"的机器保证。**
3. **措辞强度门控**：相关证据的段落里因果动词数必须为 0（动词白/黑名单机器校验）。
4. **"做不了"也必须写出来**：如样本期不足无法做事件研究，要在⑤或④里显式记录 `cannot_do` + 理由，不得静默跳过。
5. **每步可中断可续**：崩溃/刷新后从最后完成的执行项续跑（靠数据哈希 + 步骤状态位）。
6. **执行前必须告知耗时**（Pyodide 冷启动 2–5 s，面板 FE + 聚类可能数十秒到分钟），用户确认才跑。
7. **快通道（JS 手写 OLS）结果必须标"快通道·非报告用"**，不得进入论文初稿数字。
8. 七步是**顺序流水线**，但⑦机制与④稳健性在依赖上可并行（都只依赖③）——Demo 先做串行，接口预留并行。

### 4.11 R-11 结果解读引擎 `P0`

**功能名称**：结果解读（Result Interpretation）

**布局**：内置在每步执行区的「解读」视图；项目级汇总在论文初稿的对应章节。

**内容**：**规则驱动的结构化解读 → 可选 LLM 润色**两段式。

```
第一段（规则，必须做）：
  输入：result 文件的 cells（系数/SE/t/p/N/组内R²/聚类数/FE 集合）
  输出：结构化结论对象
    { claim: "数字化转型与企业创新显著正相关",
      evidence: {coef: 0.083, se: 0.034, p: 0.015, n: 18042, clusterLevel: "企业", nClusters: 2847},
      wordingStrength: "associative" | "causal",   ← 由 claim_type × 检查清单推导
      caveats: ["未处理内生性", "平行趋势仅 2 期"],
      boundCells: ["c-0031", "c-0032", "c-0038"] }
第二段（LLM 润色，可选，默认开）：
  把结构化结论写成学术语体段落；**禁止引入结构化结论里没有的数字或断言**；
  输出后跑一致性校验：段落中每个数字必须能在 boundCells 里找到。
```

**字段取值**：

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `interp.claim` | string | 一句话结论 | 必填 |
| `interp.evidence` | object | 见上 | **从结果文件读取，不由模型生成** |
| `interp.wordingStrength` | enum | `descriptive` \| `associative` \| `causal` | 由 `claim_type × checks` 推导 |
| `interp.caveats[]` | string[] | 局限与未做项 | ≥1 |
| `interp.boundCells[]` | string[] | `cell_id` 列表 | 每个数字必须绑定 |
| `interp.body` | string | 学术语体段落 | 润色后 |
| `interp.modelMode` | enum | `rule` \| `rule+llm` | 诚实标注 |
| `interp.consistency` | enum | `pass` \| `fail` | 数字一致性校验结果 |

**极限值与单位**：

| 项 | 极限 | 单位 |
|---|---|---|
| 单步解读段落 | 200–800 | 字 |
| 每段数字 | ≤ 12 | 个 |
| 因果动词（相关证据段落中） | **必须为 0** | 个 |
| 一致性校验超时 | 5 | 秒 |

**交互设计**：

| 触发 | 行为 |
|---|---|
| 查看解读 | 段落中每个数字旁有小上标 → hover 显示 `coef/SE/N`，点击跳结果表 |
| 一致性校验失败 | 整段标红 + 说明"第 N 句的数字在结果里找不到" → 回退为规则版 |
| 点「换个说法」 | 重新润色（**不改变措辞强度**，强度由证据决定） |
| 点「更保守」 | 把 `wordingStrength` 降一档重写 |
| 关闭 LLM 润色 | 全局设置项；关闭后只输出规则版（更可复现） |

**其他需要开发关注的内容**：

1. **数值一致性是硬约束**：解读里的每个数字必须绑定 `cell_id`；校验不过就**降级为规则版**，不得放行。
2. **措辞强度不可由用户"调高"**：只能调低。想调高必须回设计页补识别策略（这是学术规范，也是产品的差异化）。
3. **`modelMode` 必须暴露**：导师问"这段是不是 AI 写的"，产品要能回答。
4. 常见误读要**主动拦截**：把不显著说成"无影响"、把边界显著说成"稳健"、把异质性当机制、把相关说成因果——这四类写成规则检查。

### 4.13 R-13 三件可查面 `P0`

|---|---|---|---|---|---|
| 引用 chip | 高亮该句 | 高亮该句 | 该 chunk 全文 + 融合分 + 支持强度 | 跳页 + 高亮 bbox | 定位产出该句的步骤 |
| PDF 里选一段 | 列出引用它的句子 | **反向高亮所有引用它的段落** | 该 chunk 详情 | 保持 | 该 chunk 参与过的步骤 |
| 结果表某个系数 | 跳解读句 | 高亮对应正文数字 | 该 `cell_id` → 脚本行 | — | ③④⑤⑥⑦ 的那次运行 |
| 设计项 | — | 跳到相关段落 | 文献支撑 | — | 对应步骤 |

**字段取值**：

| 字段 | 类型 | 取值 |
|---|---|---|
| `focus.target` | object | `{kind: 'chunk'\|'cell'\|'section'\|'design-item'\|'step'\|'doc', ref}` |
| `focus.stack[]` | array | 用户"钉住"的次级高亮（≤5） |
| `focus.panels[]` | array | 参与联动的面板（用户可关掉某面板联动） |

**极限值与单位**：焦点切换响应 < 100 ms；高亮栈 ≤ 5；反向索引匹配 ≤ 500 条。

**其他需要开发关注的内容**：**只做一个焦点状态**，不做五套选中态——五套选中态必然失步。反向索引（chunk → 引用它的句子）**完全由事件派生**，不需额外存储。

#### 4.13.3 面三：进度追踪（Progress）

**功能名称**：进度追踪（三层进度）

**布局**：三层呈现 —— 顶部细进度（瞬时）/ 步骤清单（秒级）/ Job 卡（长任务）；底部常驻状态条。

| 层 | 时长 | 呈现 |
|---|---|---|
| L1 瞬时 | < 1 s | 阶段名 + 呼吸点，**不画进度条** |
| L2 秒级 | 1–10 s | 子步骤清单逐条点亮 + 累计耗时 |
| L3 长任务 | > 10 s ~ 小时 | Job 卡：结构化进度 + ETA 区间 + 置信度 + 暂停/继续 + 增量输出 + 降级徽标 |

**底部状态条常驻**：

```
阶段  ③基准回归 · 第 2/4 执行项 · 已完成 12,480/18,042 行 · 剩余约 20–40 秒（置信度 中）
模型  deepseek-official / deepseek-chat · 本次会话已用 41,203 tokens
数据  本地 · 未出网 · 你的文献与数据从未离开这台电脑        [本次将发送什么 ▸]
```

**字段取值**：见 [附录C §2 的 `ProgressEvent`](经管论文助手-附录C-进度与可观测语义.md)（沿用，不重复定义）。

**极限值与单位**：ETA 三档（high 需 ≥5 个已完成单位 + 速率波动 ≤50%）；进度事件节流 100 ms；`aria-live="polite"`。

**其他需要开发关注的内容**：

1. **降级必须显示在进度区**（"语义索引未就绪，仅 BM25"），不能只写日志。
2. **中断后从已完成项续跑**，不是从头再来。
3. **刷新后不自动复活**长任务，需用户确认续跑（避免重复消耗）。
4. **禁止假精确**：估不准就给区间 + 置信度，不给秒表。

### 4.14 R-14 项目持久化与复原 `P0`

**功能名称**：项目持久化与导出/导入

**布局**：左栏「我的项目」列表 + 项目内「导出项目」按钮。

**内容**：事件日志持久化（IndexedDB）+ 大对象（OPFS）+ 项目导出包。

**字段取值**：

| 字段 | 类型 | 取值 |
|---|---|---|
| `project.id` | string | `proj-<uuid>` |
| `project.title` | string | 自动取自命题（可改） |
| `project.createdAt` / `updatedAt` | ms | — |
| `project.status` | enum | `draft` \| `designing` \| `executing` \| `drafting` \| `done` |
| `project.eventCount` | int | 事件数（用于判断完整性） |
| `export.format` | enum | `zip`（含 `schema_ver` + `content_hash`） |
| `export.include` | object | `{events, artifacts, code, results, interpretations, paper, refusals, unverified}` |

**极限值与单位**：单项目事件 ≤ 50 万条；导出包 ≤ 500 MB；导入校验超时 60 s。

**交互设计**：新建 / 打开 / 重命名 / 删除（二次确认）；导出 / 导入（哈希校验，失败给具体原因）；导入后自动复原到导出时状态。

**其他需要开发关注的内容**：

1. **刷新后现场复原靠"事件日志 + 折叠函数"**，不需要额外设计状态持久化。
2. 导出包是**唯一同步/备份通道**，必须**可再导入还原**（哈希一致）。
3. 导出包**不含第三方文献全文**（只含引用位置与摘录片段）。
4. 浏览器存储可能被驱逐 → 启动时校验清单，提供"导入备份包恢复"。

## 5. 支撑章节

### 5.1 多 Agent 架构（LangGraph，跑在浏览器内）

**这是本 Demo 的技术核心**：整个 Agent 框架决定"AI 能不能按预期产出一篇合格论文"。

```
                         ┌──────────────────────────┐
                         │  Supervisor（总控）        │
                         │  路由 / 阶段推进 / 门禁     │
                         └────────────┬─────────────┘
        ┌──────────────┬──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼              ▼
 ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
 │ RQ-Agent   │ │ Lit-Agent  │ │Design-Agent│ │Empirics-   │ │Writing-    │
 │ 命题解析    │ │ 文献检索匹配│ │ 实验设计    │ │Agent 实证  │ │Agent 写作  │
 └────────────┘ └────────────┘ └────────────┘ └─────┬──────┘ └────────────┘
                                                     │
                                    ┌────────────────┼────────────────┐
                                    ▼                ▼                ▼
                            ┌────────────┐  ┌────────────┐  ┌────────────┐
                            │Data-Agent  │  │Model-Agent │  │Interp-Agent│
                            │ 数据清洗    │  │ 计量模型    │  │ 结果解读    │
                            └────────────┘  └────────────┘  └────────────┘
                                    │                │                │
                            ┌───────┴────────────────┴────────────────┴──────┐
                            │  Reviewer-Agent（质量门：一致性 / 措辞 / 引用校验）│
                            └───────────────────────────────────────────────┘
```

**8 个 Agent 的职责与边界**：

| Agent | 职责 | 关键产出 | 不做什么 |
|---|---|---|---|
| **Supervisor** | 阶段路由、门禁判定、失败重试、人机交互点调度 | `stage.*` 事件、`gate.blocked` | 不产出学术内容 |
| **RQ-Agent** | 命题五槽位解析、`claim_type` 判定、可行性预警 | `ResearchQuestionCard` | 不猜填槽位 |
| **Lit-Agent** | 混合检索、三类探针、分歧探测、缺口分析 | 命中集、`EvidenceGapList` | 不编造文献 |
| **Design-Agent** | 假设、变量、模型、检查清单、七步执行项 | `ExperimentDesign` + `PrecheckReport` | 不在缺字段时推进 |
| **Empirics-Agent** | 七步流水线调度、步骤状态机 | 七个步骤的三件套 | 不发散到设计之外 |
| **Data-Agent** | 数据读取清洗、变量构造、样本筛选、质量诊断 | 清洗日志、变量描述 | 不静默丢数据 |
| **Model-Agent** | 按设计跑计量模型（Pyodide + statsmodels） | `ResultTable` / `NumberInventory` | 不自造计量轮子 |
| **Interp-Agent** | 规则驱动结构化解读 + 可选 LLM 润色 | 解读文件（含 `boundCells`） | 不引入结果外的数字 |
| **Writing-Agent** | 九章初稿、风格画像、逐段生成、引用校验 | `PaperDraft` | 不一次吐全文、不越措辞强度 |
| **Reviewer-Agent** | 四类质量门（数值一致性 / 措辞强度 / 引用真实性 / 披露完整性） | `QualityReport` | 不通过则打回对应 Agent |

**LangGraph 落地要点**（浏览器内）：

| 项 | 方案 |
|---|---|
| 库 | `@langchain/langgraph` **前端入口**（有浏览器构建） |
| 状态 | `StateGraph` + 显式 `Annotation`；**状态与 DSH 事件日志同构**（每一次节点执行写一条事件） |
| 循环 | Supervisor → 专职 Agent → Reviewer 打回 → 重试（**带最大重试次数**，防死循环） |
| 人机交互 | `interrupt()` 实现"设计确认门"与逐段确认；恢复靠 checkpointer |
| 持久化 | checkpointer 落 IndexedDB；**崩溃后从最后检查点续跑** |
| 流式 | 节点内 `stream` 事件 → 前端进度（与附录C 的 `ProgressEvent` 对齐） |
| 计算 | 计量执行走 Web Worker + Pyodide，**不阻塞主线程** |
| 与 DSH 一致 | 事件词汇、turn/step 语义、工具管线、投影契约与本地 App **同构** |

> **完整架构、节点契约、状态定义、事件词汇、框架一致性验收见 [附录A](经管论文助手-附录A-Agent框架一致性契约.md)。**

### 5.6 非功能需求

| 项 | 指标 |

## 6. 术语表

| 术语 | 含义 |
|---|---|
| **命题（RQ）** | 用户提交的研究问题，五槽位 + `claim_type` |
| **实验设计（Experiment Design）** | 七分区方案：研究问题/假设/数据样本/变量/模型/检查清单/预期结果 |
| **设计确认门** | 唯一硬门禁，未确认不跑数据 |
| **七步实证** | 数据清洗→描述统计→基准回归→稳健性→内生性→异质性→机制 |
| **三件套** | 每步产出的「可执行代码 + 结果文件 + 结果解读文件」 |
| **`claim_type`** | 用户期望的结论类型：因果/相关/描述/机制/政策评估 |
| **`wording_strength`** | 允许的措辞强度：`causal`/`associative`/`descriptive`，由 `claim_type` × 检查清单推导 |
| **`cell_id`** | 结果表里一个数字的唯一编号，正文数字必须绑定它 |
| **`boundCells`** | 解读段落中每个数字绑定的 `cell_id` 列表 |
| **风格画像（`StyleProfile`）** | 从参考文献提取的形式特征（句长/连接词/段落数/图表引出/结论口吻） |
| **三件可查面** | 阶段可查（why-trace）、关联同步（Focus Sync）、进度追踪（Progress） |
| **拒答（Refusal）** | 结构化输出"做不了 + 依据 + 你能补什么 + 本次不做的事" |

## 7. 一句话交付建议

**这一版的产品赌注是一句话**：

> **学生不是需要一个更聪明的聊天框，而是需要一个能带他把一篇合格论文跑完、并且每一步都留下过程性材料的助手。**

**保留的**：内容寻址的幂等清单、OPFS+IndexedDB 分层存储、BM25+本地向量混合检索、Pyodide 可复现执行、证据包导出、14 条降级路径、八个宿主无关端口、与本地 App 同构的事件溯源内核、三件可查面。

**砍掉的**：独立的学习模式 Tab、"零幻觉"承诺、服务端/硬编码密钥、把"可追溯"当作对外主卖点。

**必须新加的**：**LangGraph 多 Agent 编排（浏览器内）**、**实验设计确认门（执行层强制）**、**七步实证流水线**、**每步三件套过程文件**、**结果解读的数值一致性硬校验**、**《中国工业经济》默认风格包**、**模型连通性检测**、**两栏空状态与资源库抽屉**。

> 判断这条路线是否成立，最终只看一件事：**现场给一个学生没准备过的命题，30 分钟后他手上是否有一份导师能看懂、并且能指出"下一步该改哪里"的材料。**
